SHA-256: `7906eba09fcfb74fa70bb579a048d9ca413d2e48cb33c3b232df5d829688c80e`. It corroborates historical roles 9–12 and permissions 59–87. It is a local historical export, not an independently signed recovery certificate.
- Users 5/6 match the historical ID, company, email, name, authoritative role and creation time. Historical roles `superadmin`/`admin` map to current IDs 4/1. Only `user_roles.role_id` changed; pivot IDs, user IDs and assigned timestamps were retained. Original values are preserved in the untouched SQL snapshot and two new immutable rehearsal audit records. Effective permission hashes match before/after.
- No complete users 1/10 or PO 2 were found in the available logical exports. The historical payment-change fragment is insufficient to reconstruct PO 2's supplier, currency or lifecycle. No parent was invented. The preserved physical recovery copy remains available for specialist investigation.
- PO 1 also has a pre-existing chronology conflict: July 17 history/line 1 coexist with a July 29 `created` snapshot under the same ID and a different supplier. This corroborates mixed historical identity, but the exact original destructive/import operation is unproven. It is an additional business-coherence concern, not an additional FK violation or an authorized correction.
- The source Document Center has zero document records. No associated original statement/invoice evidence was fabricated. Existing attachment-root files were preserved separately.
- **Resolved** means the relationship was actually verified valid in the indicated database. **Evidence Required** is not a repair. **Blocked** needs a policy/source decision. **Approved Exception** would still be an invalid FK; none has been approved. Known-parent ownership checks found no cross-company mismatch, but missing-parent ownership remains unverified.
