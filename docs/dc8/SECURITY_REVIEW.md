# Targeted security review — DC8

This review uses the [OWASP ASVS 5.0.0](https://asvs.owasp.org/) categories relevant to the changed surfaces. PASS means a specific inspected/tested boundary, not every requirement in a category or a certified ASVS level. It is not a penetration test.

| Area / concrete finding | Status | Evidence / decision |
|---|---|---|
| Authentication: distinguishing unknown users/wrong passwords; missing failed-attempt signal | IMPROVED | Generic credential errors, bounded inputs, existing login throttles and sanitized threshold events. Email verification state is disclosed only after a correct password. |
| Authentication: optional phishing-resistant factor | IMPROVED | Library-backed passkeys require user verification, exact trusted origin, RP hash, challenge/signature and owner/counter/backup state. [WebAuthn Level 3](https://www.w3.org/TR/webauthn-3/) guides supported browser behavior. Full Level-3 conformance is not claimed. |
| Enforced administrator factor could be replaced/disabled using only a password session | IMPROVED | Recent-authentication service inherits current administrator passkey policy. Enrolment and policy removal reject password-only sessions. Focused regression asserts this boundary. |
| New/reset/temporary password policy | IMPROVED | Central 15-character floor, 72-byte limit prevents bcrypt truncation. Existing passwords are not invalidated or exposed. Breached-password corpus screening remains deferred for an offline-compatible provider/policy. |
| Passkey recovery / privileged takeover | IMPROVED | No security questions. Verified-email password reset cannot disable passkey policy. Owner recovery is CLI-only, requires maintenance plus a separately escrowed key/hash, exact user/company and reason, and revokes factors/sessions with audit. |
| Session management / token lifecycle | IMPROVED | JWT session binding, current token version, expiry, rotating hashed refresh token, immediate session revoke and disable/role-change invalidation. Old API tokens have a bounded 30-day transition and cannot step up. |
| Persistent browser bearer storage | DEFERRED | Existing localStorage/JWT architecture retained. CSP and token/session expiry reduce exposure but do not make bearer storage HttpOnly. A cookie/session architecture migration requires a separate web/desktop design review. |
| Access control: shared role definitions could not express company-specific restrictions | IMPROVED | Company overrides plus existing defaults; no global permission reset. Payroll tests prove capability AND user permission, and second-company independence. |
| Inactive service identity could inherit an employee role if modified | IMPROVED | Gateway requires exact inactive `integration` identity; employee administration rejects conversion. MCP/API credentials retain per-request current scopes and company entitlement checks. |
| High-risk payroll, finance, fiscal and integration surfaces | PASS / IMPROVED | Existing service/permission authorities preserved. Sensitive configuration/export/credential endpoints add recent authentication. Normal stock operations do not acquire a mandatory reauthentication prompt. |
| API input / arbitrary execution | PASS | Allowlisted capabilities, scoped IDs, typed WebAuthn payloads, fixed RSA verification algorithm, bounded metadata and strict signed artifact filenames. No arbitrary code/SQL/MCP write action added. |
| Cryptography / secret preservation | IMPROVED | Laravel encryption and existing authenticated backup crypto reused. New encrypted installation witness, existing-cipher precheck on migration and original-key comparison before restore/update. Standard RSA-SHA256 issuer verification; private issuer keys are external. [Laravel encryption guidance](https://laravel.com/framework/docs/12.x/encryption) applies. |
| License isolation / offline expiry | IMPROVED | Issuer signature, company/installation binding, signed dates/capabilities, clock high-water mark and explicit grace. Existing records remain readable after expiry. Not resistant to a host administrator replacing the application itself. |
| Update metadata alone did not bind staged executable files | IMPROVED | Signed artifact hashes AND whole immutable staged tree. Added `backend/unlisted.php` in the fixture is rejected. Verification runs from current trusted code before candidate execution. No automatic rollback is asserted. |
| Backup existence mistaken for verification | IMPROVED | Actual archive authentication/checksums, key/engine/database compatibility, timestamp and current file hash required for checkpoint/preflight. A standalone healthy fixture passes the full preflight without changing application code/schema. |
| File handling / private documents | PASS | Existing extension/type/size/name/Office-content checks, private provider, company/workforce authorization, checksum download and sandbox response retained. Search remains metadata-only. No antivirus certification. |
| Optional malware scanning | DEFERRED | Use the existing document provider/upload boundary for a deployment scanner; do not treat MIME checks as malware scanning. |
| Web configuration | IMPROVED | API no-store, nosniff, frame/referrer restrictions and exact origin configuration. Production-style frontend CSP is exercised by the representative browser journey with no violations. HTTPS/HSTS/secure-cookie requirements remain deployment-specific; bearer API is not cookie authentication. |
| Security audit / telemetry / support | IMPROVED | Separate security events, company-scoped bounded exports, technical-only support allowlist and existing safe incident reference linked to W3C context. No raw logs, request bodies, SQL bindings, documents, credentials or compensation values in the support bundle. |
| PHP security runtime | IMPROVED | Official 8.3.36 fixes [OOM corruption](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w) and [stale global state](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp). Windows build 8.3.36-1 is verified against PHP's published SHA-256; no major PHP upgrade. |
| Composer / frontend / declared Python advisories | IMPROVED | Compatible patches applied; final audits report no known advisories. This does not certify every OS/native dependency. |
| Electron and packaging dependencies | DEFERRED — RELEASE BLOCKER | Full audit: 1 high / 15 moderate; no critical advisory reported. Current Electron 41.10.7 requires a separately reviewed major upgrade. Some advisories have feature-specific conditions, but the distribution gate remains closed. [Electron advisories](https://github.com/electron/electron/security/advisories) and [breaking changes](https://www.electronjs.org/docs/latest/breaking-changes) inform the required review. |
| OAuth/SAML/billing/vertical modules | NOT APPLICABLE | None introduced. DC7 MCP remains read-only stdio; no new remote OAuth server or billing provider. |
| Host / native authenticator / actual production upgrade certification | DEFERRED | Needs the target host, issuer trust configuration, supported database/runtime decisions, recovery exercise, physical authenticator review where required, and actual TLS/Nginx/systemd validation. |

No remaining **critical** application finding was identified in this bounded review. The high desktop advisory and commissioning gaps are material; commercial deployment is not approved by these local results. DC9 was not started.
